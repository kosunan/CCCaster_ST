# Steam版の元入力ポーリング境界

担当1、2026-09-11。静的解析と独立ヘッダーを実装。実ゲームへの適用、コンパイル、入力実機確認は親担当へ引き継ぐ。この記録はSteam対戦成功を意味しない。

## 確認した処理

対象はSHA256 `11270cf2da851054aa6c1bff309d50b042429abd936dca5df833bcd1de5e6c46` のSteam EXE。以下はImageBase=0x400000時の基準VAであり、実行時にはロード先とRVAで解決する。

- `0x5194cc`が`[0x5ca9b8] = 0x7d8428`を設定する。格納ポインターへASLR差分を重ねて加算しない。
- `0x476200`はECXに入力元オブジェクトを受け、ESI=ECX+0x18、EDI=0から4プレイヤーを0x14刻みで走査する。引数なしthiscall、RETのみ、ESI/EDIを保存する。
- `0x476216..0x47622a`はXMM0をゼロ化、方向・補助2個・ボタンをSSEでクリアし、最後の補助DWORDもクリアし、物理入力の仮想関数へ `(playerIndex, output)` を渡す。仮想呼出しはRET 8で2個の引数を回収する。
- **同じ処理が`0x48f9a9..0x48f9bd`にもインライン化されている。** 最初の関数だけのパッチではこちらで同期入力が破壊される。
- EXEのmemory-mapped imageを21B完全一致で走査すると、上の2か所だけが一致する。他形状の書込みが存在しないことの証明ではない。
- いずれも後続はEDI++、ESI+=0x14、EDI<4でループ。通常関数はRETし、インライン側は`0x48f9cd`から派生入力構築`0x476240`を呼ぶ。
- `0x4762c8`は元方向+0x18を読取り、`0x4762cf/0x4762d4`は補助+0x1c/+0x20を読取り、`0x4762e0`はボタン+0x24を読む。派生構築は変更しない。

## 物理入力経路

`0x5194ad`が入力デバイスオブジェクト`0x5b6960`を`[0x7d4df4]`へ設定する。コンストラクター`0x56a4b2`のvtableは`0x589ff4`、slot+0x14は`0x4effb0`。

`0x4effb0`はプレイヤーごとのデバイス状態を選択して`0x4f0140`を呼ぶ。この関数は方向を条件付き設定し、物理ボタンを元入力+0xcへORし、キーボード入力も`0x4f0040/0x4f00d0`から取り込む。旧版NOPの対応先を単にクリア命令へ追加するだけでは、このORにより同期入力へローカル入力が混入する。

`0x4f0140`で確認した元出力への書込みは`0x4f0165`、`0x4f0174`、`0x4f017c`、`0x4f018c/196/1a0/1aa`、`0x4f01d7/1de`。ポーリング本体とキーボードを含むコピー呼出しをまとめて省略し、CCCasterの独立InputTimeline/DirectInputHookが採取した値をGameMem経由で供給する。

## 実装と組込み条件

`src/core_dll/mbaa_mem/SteamInputPatch.hpp`に次を実装した。

1. 版指定、主EXEのロード先、RVA範囲、VirtualQuery、直前のASLR済み絶対オペランド`base+0x3d4df4`、元21B、後続9Bを照合する。
2. 2か所とも保護変更できるまで書込みを始めない。
3. 各21Bを`xorps xmm0,xmm0; xor eax,eax; mov [esi+4],eax; mov [esi+8],eax; mov [esi+0x10],eax`とNOPへ置換する。方向[ESI]とボタン[ESI+0xc]を保持。仮想callと引数pushを共に消すためスタック差分はゼロ。
4. 命令キャッシュをflushし、ページ保護を復元する。flush失敗時には元命令へ戻す。保護/復元の重大失敗は`FatalProtectionFailure`を返し、呼出側でゲームを再開しない。

呼出しは`steam_input::Apply(LoadedImage, Edition::Steam20170105)`。必ず親の完全な既知版照合を先に実施し、ゲームスレッドを起動・再開する前に適用する。関数は自身で版ハッシュを計算しない。`Rejected`もSteam入力を開始せず起動失敗にする。旧版の`ApplyStartupPatches`と併用しない。GameMemの入力元参照も同時にSteamへ切り替える必要がある。

上記コードはEAXとXMM0を変更するが、いずれも元callで変更可能なvolatileレジスター。ESI/EDI/EBX/EBP、ESPを維持する。ループ継続のフラグは後続のINC/ADD/CMPで作り直す。同期対象外の補助値は毎回ゼロになるため、物理アナログ成分を取り込む旧版の補助値とは差がある。対戦方向・ボタンの同期にはこの除去を選択したが、メニュー／トレーニング機能の実機確認が必要。

元入力の採取後も`0x48a7ce`のvtable+0x18呼出しは残る。物理入力の別の副作用、Steam overlay、Esc/Fn、F4設定入力遮断、P3/P4の状態、再計算時の呼出経路は実機未確認。

## 確認の根拠

`build_logs/steam_analysis/steam.asm`の上記VAと実EXEの21B照合を使用。置換21BをCapstoneで再逆アセンブルし、3個の補助DWORDだけをゼロ化し、push/pop/callを含まないことを確認した。元ゲームや既存プロセスへの書込み、起動、終了は実施していない。ビルドと実行確認は統合担当が実施する。
