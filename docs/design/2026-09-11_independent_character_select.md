# Steam版の独立キャラクター選択

対象: Steam 2017-01-05、x86。独立プロジェクト内だけに適用。

キャラセレ中の各フレーム入力の同期と相手入力待ちを外し、各自の独立入力時計・中央バッファで通常更新する。相手の途中カーソルは転送せず、所有者が確定したキャラ・ムーン・色を revision/ack 付きで繰り返し送る。ステージはホストが所有し、双方の確定状態と受領確認が揃ったらロードを許可する。待っている間も背景・描画・入力時計は進む。戦闘開始時の世代・RNG合流、D2/R4の予測上限と保存表は維持。

通信はSTN1/CCS1、wire 10を維持し、同期ヘッダ byte 7=1 を必須化。旧DLLとの混在は拒否。カニファン版とのクロスプレイは対象外。F4遮断・未確定B抑止・再戦とリプレイ抑止は既存経路を維持。

## Steam EXEの照合

すべて preferred VA から実ロード先+RVAへ解決し、ASLRを無効化しない。参照逆アセンブルは `build_logs/steam_analysis/steam.asm`。

- P1 selector mode=0x7B4424、selector/character/moon/color=+0x0C/+0x10/+0x14/+0x18。P2=+0x24。
- ステージ selector=0x7B6228。ランダム色の親ポインタslot=0x7B433C、子stride=0x1DC、flag=+0x38。
- ステージ入力結果のフック=0x47FFED、署名 `83 F8 FF 74 10`。正規関数0x4E29E0の結果EAXだけを保留し、ロード移行の許可時に255を返す。
- ステージ0はロード時0x4860C0から0x486260へ入って抽選される。独立選択のままでは両窓で別ステージになったため、ホスト確定時だけ正規抽選関数0x486260を呼び、具体的な結果を共有する。関数先頭署名 `55 8B EC 83 EC 08` も照合する。ロード側0x4860F1はそのステージ番号を背景番号へ反映する。
- ロード後の確認はP1 color/character/moon=0x7B4374/+4/+0x10、P2=+0x2C。選択欄だけでなく実ロード値も比較。

## 検証中に見つけた問題

最初の `bounded_real_20260911_141716` は独立選択分岐がIPC起動完了通知を飛ばし、ランチャーの同期待ち時間切れで終了した。接続完了を選択確定から独立して通知する修正を追加。

`bounded_real_20260911_141830` はキャラ・ムーン・色は一致し784確定戦闘Fの比較差分0だったが、ランダムステージが22/39に分かれた。成功扱いにはせず、上記のホスト単独抽選へ修正。比較器の最低1000Fもこの試験では未達。
