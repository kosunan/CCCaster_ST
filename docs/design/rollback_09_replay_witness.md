# 確定入力による4フレーム再計算の保存表検査

2026-09-11。担当9。実装先は `src/core_dll/engine/SceneRunner.cpp`。

`CCCASTER_TEST_ROLLBACK` を設定したホストで、既存の強制4フレーム戻しを保存表の実機検査にする。環境変数は SceneRunner 初期化時に読む。通常起動では検査用ベクターの確保、保存、比較を行わない。

自然な予測訂正がないことと、`history.Confirmed() >= next - 1` を追加条件にした。元の条件（戦闘中、予測可能、世代開始から400フレーム超、前回から180フレーム超）も維持する。自然な訂正を強制検査で置換しない。

ゲームスレッドで `BeginReplay` と復元の前に `SaveSnapshot` の全blobを期待値として保持する。同じ確定入力で4フレームを再計算し、元のtargetへ到達して `EndReplay` を終えた直後、通常の次フレーム入力を書き込む前に再保存する。全バイトを走査して比較するため、Steamの資源世代番号と入力/RNGカーソルの末尾も検査対象になる。同一プロセス内の比較なのでポインター値をASLR正規化しない。

ログは `[RollbackWitness] BEGIN/PASS/FAIL`。FAILには保存失敗の理由、または異なるバイト数・最初のblob内オフセット・期待値/実値を出力する。不一致を許容値として隠さず、既存のFail経路でセッションを停止する。検査自体の追加保存・走査時間を通常更新の精度評価に混ぜないこと。

担当内ではコードの条件と処理順を確認。共通ビルドと実ゲーム起動は統合担当へ委ねたため、実機成功はまだ記録していない。PASSは保存対象全体の同一入力再計算一致を示すが、保存表から漏れた状態の不存在や全キャラクター・全ラウンドの網羅を単独で証明しない。
