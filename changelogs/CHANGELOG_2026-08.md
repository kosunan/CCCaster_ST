# build: harness と単体テストを Linux でも動くようにした — 検証を実機から切り離す

## 2026-08-13

これまで、同期ロジックを1回検証するのに Windows・実ゲーム2窓・GUI が必要だった。
harness も Windows 専用でしか動かず、実機に触れない状態では**コンパイルが通るかどうかすら
確認できなかった**。今後の作業はフレーム空間の作り直しで、試行回数がそのまま速度になる。
先に検証の敷居を下げた。

OS 依存処理の窓口を `common/Platform.hpp` 1枚に集約し、`windows.h` を叩いていた箇所を
そこへ寄せた。`#ifdef _WIN32` を各所に撒かなかったのは、撒くと「Linux では通るが Windows では
違う経路」が静かに増えるため。窓口が1つなら差分はそのファイルを読めば全部分かる。

`SleepMs()` と `RealSleepMs()` を分けたのは、実機では `TimeHooks` の SleepBypass によって
`Sleep(1)` が `Sleep(0)` に化けるという**既存の挙動を変えないため**。既存の呼び出しは前者に
対応させ、挙動は現状のまま据え置いた。CPU を返す修正（AUDIT A-4）は別の変更として行う。
1つのコミットで2つのことをすると、デシンクの再現が変わったときにどちらが原因か分からなくなる。

集約したついでに、時刻計算のオーバーフローを直した。`QPC * 1000000 / freq` は
乗算が先に溢れるため、10MHz の QPC では**約10.7日で符号付きオーバーフロー**する。
商と剰余に分けた。元は `WasapiClock` にあったもので、集約により全時刻取得の
単一経路になったため、ここで潰しておく必要があった。

WASAPI は `#ifdef` で切り、Linux では単調時計に落ちる。これは元々「オーディオデバイスが無い
ヘッドレス環境」用に用意されていた経路で、Linux のために新設したものではない。ただし
ドリフト特性は別物なので、**Linux の harness はクロック品質の検証には使えない**。

`IpcManager` は Linux 版を no-op にした。呼び出し側（`SceneRunner`）に `#ifdef` を入れると
処理順が OS で変わるので、受け側で吸収する。IPC の相手は Windows 専用の CLI ランチャーであり、
Linux で本当に必要になったら shm_open で実装する。

`run_pair.sh` は `run_pair.ps1` と判定・出力形式を意図的に揃えた。物差しが違うと
「Linux では OK だが実機では NG」の切り分けができなくなる。

Linux ネイティブの harness で、実機由来のデシンク（`WT` が netFrame=231 付近で分岐）が
Windows harness と同じ形で再現することを確認済み。

# build: 64bit ビルドを止め、対象 Windows バージョンを固定した

## 2026-08-13

`AGENTS.md` が落とし穴の筆頭に「32bit 限定」を挙げていながら、ビルドシステム側では
何も防いでいなかった。64bit でも DLL は生成でき、注入だけが**無言で**失敗するため、
症状から原因に辿り着けない。configure の時点で落とす。

`_WIN32_WINNT` はこれまでツールチェイン既定値任せだった。MSYS2(GCC15, 既定 Win10) では
通るが、既定が古いツールチェインでは `inet_pton` / `inet_ntop` が未宣言になる。
どの環境でも同じ API 集合が見えるよう Windows 7 に固定した。ここを上げると
古い環境で動かなくなるので、上げる場合は理由を書くこと。
